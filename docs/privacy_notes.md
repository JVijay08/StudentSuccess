# StudentSuccess AI Privacy Notes

## Purpose

StudentSuccess AI is an educational planning and academic-support tool designed to help students organize coursework, tasks, workload check-ins, course pathways, portfolio goals, and educational recommendations.

**Important:** StudentSuccess AI is not a medical service, therapy tool, college-admissions outcome predictor, or financial-advice platform.

## Data Minimization

The application should collect only data needed for a visible feature.

Appropriate examples of local student-entered data include:

- First name
- Grade level
- Graduation year
- Current and target GPA
- Study hours per week
- Course preferences and rigor expectations
- Career or academic interests
- Tasks and deadlines
- Workload and burnout check-in responses
- Portfolio activities and goals

These fields are intended to support personalization, planning, recommendations, and progress tracking.

## Data the Project Should Not Collect

StudentSuccess AI should not collect:

- Passwords outside the authentication system
- Government ID numbers
- Social Security numbers (SSN)
- Home addresses
- Precise location data or GPS coordinates
- Financial account information or payment details
- Medical records or physical health information
- Therapy records
- Diagnoses or mental-health assessment results
- Real college-admissions decisions or outcomes
- Private records about other students without explicit permission

## Burnout and Wellness Disclaimer

Burnout-related outputs are educational workload and schedule-balance estimates only. They are **not** medical, mental-health, or diagnostic results.

The app should encourage students to talk with a trusted adult, school counselor, teacher, or healthcare professional when appropriate, rather than presenting itself as professional support. StudentSuccess AI is a planning and organization tool, not a substitute for professional mental-health care.

## Synthetic Data and Machine Learning

Later machine-learning models will use synthetic demonstration data generated by the project.

Key principles:

- The data will not represent real student records
- The models are educational demonstrations
- Model outputs must be labeled as estimates, not certainties
- The project should not claim to predict real college-admissions outcomes or likelihoods
- Predictions and recommendations should include clear limitations and caveats

## Local Storage and Security Direction

Early versions will use local SQLite storage for development.

Later security work should include:

- Hashed passwords using Werkzeug
- Session-based authentication and secure session handling
- Server-side input validation
- Access controls so users only see their own information
- No hard-coded passwords, API keys, or secrets in source code
- Environment variables for future secrets and configuration

## Core Privacy Rule

> Only collect information needed for a visible StudentSuccess feature.
